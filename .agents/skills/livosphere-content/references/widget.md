# Самостоятельный виджет часов

Прочитай `docs/CONTENT.md`, текущий workspace часов и native implementation в `android/widgets/runtime`. Существующие debug layouts — технические примеры, их стиль не является принятым стилем нового продукта.

Brief определяет digital/analog и визуальную идею. S показывает время, M/L — время и дату; три размера — варианты одного продукта. Сохраняй читаемость на реальных host bounds, системные 12/24h, locale и часовой пояс. Батарея, погода и другие виды widgets требуют изменения продуктового scope.

HTML показывает каждый размер отдельно в масштабе телефона, контраст на светлом/тёмном фоне, несколько сложных для композиции значений времени/даты и ожидаемое нажатие. Dashboard допустим для навигации, но не заменяет проверку отдельного viewport. Native размеры и текст не определяются размером browser-картинки автоматически.

Базовая реализация — RemoteViews с TextClock, ограниченный AnalogClock по подтверждённому probe. Не обещай произвольное движение, bitmap ticking или Compose внутри host на основании HTML. Существенный риск конкретного выбранного оформления проверяется узким native spike до его финального художественного принятия; исторический полный suite повторно не запускается без причины.

После AP-HTML интеграция использует clock runtime, собственные resources S/M/L, уникальный widgetId, существующие configuration/target routes. Проверки выбираются для времени/даты, реальных размеров, add/edit/cancel и независимости экземпляров. Изменение арта не требует заново переписывать settings/provider.

AP-IMAGE обоев для этого режима N/A. После установки последующего продукта сохранённые экземпляры первого должны продолжать ссылаться на свой ID и настройки.
