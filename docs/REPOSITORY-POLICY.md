# What belongs in Git

This is the working source repository. Keep enough context here for another developer or agent to build the app and continue a change from a fresh clone.

## Track

Code, tests, Gradle wrapper and configuration, dependency versions and lockfiles, manifests, required Android assets, font licenses and asset provenance. Track `pen-design/` working sources/dependencies, `docs/planning/`, `docs/specs/`, canonical `docs/development/sprint-status.yaml`, shared `.agents/bmad/config.toml`, `scripts/`, `.agents/skills/` with their templates/data/helpers, `AGENTS.md`, and shared documentation. New shareable content workspaces go in `docs/content/`; accepted decisions go in `docs/decisions/`.

README images and artwork needed by the application are tracked under their separate artwork terms. Do not blanket-ignore image extensions, XML, Markdown, JSON or agent directories. An artifact's file type alone does not make it private.

`.env.example` contains empty or demonstrative values and is tracked. Owner-specific values belong in the ignored `.env`; keystores stay outside the checkout.

## Ignore

- Local SDK paths, personal IDE settings, credentials and signing key/export files.
- Gradle/build/cache directories, generated APK/AAB/APKS and memory dumps.
- Python/Node environments and caches, including generated bytecode in skills.
- Restored `_bmad/` runtime and `_bmad-output/` private planning workspace.
- Temporary design exports/backups/scratch directories; legacy root `design-system/` output remains private.
- `.local/` for raw device captures, build/run logs, private release evidence and other local work products.

`pen-design/` contains tracked editable designs and their required assets. Only its temporary `exports/`, `backups/`, `tmp/`, `.working/` and named backups are ignored. The root legacy BMAD output is ignored; accepted planning lives under `docs/planning` and implementation context under `docs/development`. Public content design records under `docs/content/` remain trackable. Do not store the only explanation of a code change in an ignored BMAD output or in chat: preserve the shareable result in documentation and the PR.

## Evidence and releases

Put raw logs and signed candidate payloads in `.local/evidence/` or another private external directory. Commit a concise, redacted report when it helps future work: command, source revision, artifact hash, device/OS/host where applicable, result and limitations. Inspect screenshots for personal data before adding a reviewed selection to documentation.

Release binaries belong in an explicitly approved distribution channel, such as GitHub Releases or RuStore, rather than ordinary source commits. Publishing them still requires the owner's instruction and the applicable artwork permission.

## Before committing

Inspect `git status`, staged filenames and the final diff. Run `git diff --cached --check` and the checks chosen for the change. Never use `git add -f` on a signing key, credential file or raw owner evidence to bypass the policy.

`.gitignore` does not remove an already tracked file or erase its history. If private material was tracked accidentally, stop, identify its scope and arrange removal; for an exposed credential, revoke or replace it through the owner. Do not print the credential in an issue or review.
