# Addendum к PRD Livosphere

Этот companion хранит технические границы и историю выбора, которые не нужно разворачивать внутри [PRD](prd.md). Текущий источник направления — [решение 2026-09-09](../../decision-2026-09-09-phone-themes-pivot.md), полномочий — [апрув миграции](../../approval-2026-09-09-phone-baseline.md). Старый addendum сохранён в архиве (исторический материал; не является зависимостью текущего документа); его Wear-топология и общий зелёный стиль не являются действующими правилами новой поставки.

## 1. Граница требований и технических решений

Владелец делегировал техническую детализацию исполнителю. Выбранные API, расписание фаз, геометрия размеров, настройки экземпляров, packaging и ограничения renderer фиксируются как решения исполнителя в [Architecture Spine](../../architecture/architecture-Livosphere-2026-09-01/ARCHITECTURE-SPINE.md) и [phone contracts](../../architecture/architecture-Livosphere-2026-09-01/phone-contracts.md). Это не дословные слова владельца и не device PASS.

Техническая неизвестность не создаёт повторную очередь вопросов к Якову. Исполнитель задаёт проверяемый контракт, выделяет ранний spike при риске и сохраняет границы неподтверждённого. Если Android не воспроизводит принятый художественный результат, изменённое изображение/HTML возвращается владельцу; делегирование API не разрешает молча менять art.

## 2. Поставка и магазин

Новые наборы встроены в единое phone-приложение и поступают с его обновлением. Обои и widgets остаются независимыми пользовательскими поверхностями, хотя поставляются одним артефактом. Прежний вариант отдельного пакета на набор сохранён как историческая альтернатива, не обязательство первого выпуска. Не создавать лишний пакет ради метрики.

RuStore — первый канал. Product logic, модель статусов и настройки не должны зависеть от него; поставка отвечает за подпись, карточку, ссылки, обновления и требования магазина. Смена канала не означает нулевых интеграционных затрат или доказанную совместимость. Другие магазины рассматриваются отдельным решением; текущий апрув документов не разрешает публикацию.

Старый release candidate `0.1.0-rc.1` и Wear-пакет не являются новым phone-кандидатом. У нового артефакта свой состав, hashes, результаты проверок и доказательство реальной установки/обновления из RuStore.

## 3. Локальные наборы и независимое состояние

Контентный контракт включает устойчивый ID, wallpaper contribution, clock-widget contribution, preview, authored phase/effect metadata, размеры и допуск debug/release. Registry и ресурсы генерируются из канонического manifest; ручной параллельный реестр не нужен. Конкретная схема/версия принадлежит Architecture.

Разделяются: рассматриваемый набор; применяемые обои и настройки его scene; конфигурация каждого экземпляра часов. Глобальный `selectedSet` не переключает все поверхности. Виджет привязан к своему системному ID; restore/remap обрабатывается без потери соседних конфигураций. При доступных старых данных конфигурация переносится на новый ID без потерь; при их отсутствии пользователь явно настраивает экземпляр заново, без чужой темы по умолчанию. Текущий `allowBackup=false` не даёт обещать автоматический перенос между телефонами; callbacks восстановления и проверка актуального времени после process death остаются обязательными. Известный ID и конфигурация не доказывают текущую видимость на HOME/LOCK.

Для wallpaper preview важна изоляция: примерка B и её отмена сохраняют применённые A. Каждый Engine имеет собственное состояние. Рабочий вариант из Sprint Change Proposal — отдельный системно выбираемый service для wallpaper contribution с общим engine; окончательное решение и границы проверяются в Architecture, не следуют из удобства HTML.

«Контур» целиком debug-only: assets, preview, registry и компоненты не попадают в публичный artifact. Второй визуально иной fixture подтверждает независимость хаба; он не является вторым утверждённым контентным набором. Отсутствие принятого public content вызывает понятную ошибку допуска, а не скрытый выпуск «Контура».

## 4. Обои: время, объекты и ограничения

Новая сцена имеет рассвет/день/закат/ночь по местному времени. Fixed local schedule без location — допустимое делегированное решение; конкретные границы и обработка даты/пояса/ручного изменения времени фиксируются в phone contracts. Использование системного dark mode прежней реализации заменено; плавный переход между фазами и ручной phase lock необязательны.

При создании каждых обоев описываются слои/объекты, движения, входные сигналы, authored levels и порядок отключения. Три предопределённых уровня из SCP — технический default для проработки, не обязанность владельца вручную конфигурировать каждый эффект. Верхний уровень содержит полный принятый художественный состав. Tap/swipe имеют отдельный пользовательский переключатель; debug controls для отдельного эффекта и фазы не становятся UI продукта автоматически.

Ограничения обладают приоритетом над художественным default: невидимая поверхность не рисуется, off остаётся статичным, reduced/power не обходятся, неизвестный power-сигнал безопасен. Зарядка — условная локальная capability конкретной сцены. Недоступные tap/offset на launcher не ломают основу и не подтверждаются одним preview.

Сохраняется Canvas-first и общая инженерная основа; переход renderer обсуждается при измеримом нарушении бюджетов либо согласованном невоспроизводимом эффекте. Архивные правила статичной геометрии и G1…G6 «Контура» относятся только к нему, не запрещают движение объектов новых тем.

## 5. Widgets: ранняя проверка выразимости

Новый AppWidget — самостоятельная native-поверхность. WFF, Compose preview, HTML и API reference не являются его реализацией. [SCP §5](../../sprint-change-proposal-2026-09-09.md) содержит первичные Android-источники, проверенные 2026-09-09; они используются как documentation evidence, а не как результат Livosphere на устройстве.

Архитектурная проработка должна учитывать ограниченный набор views RemoteViews, host-rendered часы, локализованные 12/24 и дату, перезапуски/изменение времени, восстановление ID и независимость экземпляров. Нельзя объявлять частый app-provider refresh источником точного времени только потому, что HTML умеет обновляться каждый кадр. Стрелочный дизайн проверяется отдельно на выбранных API/host до принятия сложного art.

Малый вариант — время; средний/крупный — время и дата. Геометрия определяется с учётом реальных launcher cells и resize bounds. Конкретный набор может иметь аналоговый или цифровой формат; требование обоих отсутствует. Не добавляются батарея, погода, здоровье, WFF-AOD и обязательная анимация виджета.

Выбор приложения часов проектируется адресно, без автоматического широкого запроса пакетов. Проверяются отсутствие приложения, удаление после настройки и безопасное повторное назначение. Request/pinning callback, сохранённая конфигурация и видимость экземпляра — разные факты; отсутствие callback не даёт окончательного success/failure.

Lock screen исследуется по host/устройству: наличие, добавление, размеры, время/дата, действие в заблокированном состоянии и аутентификация. При подтверждённом пути его реализуют. Неопределённый host получает UNKNOWN; версия Android сама не разрешает обещать универсальный LOCK. Это не screensaver и не замена штатных системных часов.

## 6. Художественный процесс и независимые области UX

UX-области: `hub`, `wallpapers/<id>`, `widgets/<id>`, связь `sets/<id>`; прежние `watchfaces/<id>` остаются deferred-историей. Канонические решения и статусы находятся через [UX-индекс](../../ux-designs/ux-Livosphere-2026-08-31/approval.md). Общие документы задают ссылки/границы, не дублируют локальные DESIGN/EXPERIENCE.

Хаб сохраняет свою палитру, шрифты, компоненты и движение независимо от темы. Архивный green/OLED MASTER и прежние объединённые макеты не задают ему новые токены. Выразительный preview/основное действие не превращаются в технический dashboard, checkout или длинный рекламный landing. Разные тестовые preview проверяют независимость, не расширяют релизную коллекцию.

Процесс определён [контрактом контента](../../ux-designs/ux-Livosphere-2026-08-31/sets/CONTRACT.md) и [решением 17 сентября](../../sprint-change-proposal-2026-09-17.md): widget → HTML S/M/L → approval → Android; wallpaper → image approval → HTML approval → Android; set объединяет выбранные части. Подключение, emulator и APK обязательны для native handoff. Отсутствующая часть не создаётся ради старой упаковки.

Скилл/шаблоны готовятся в 12.1/12.2, первый авторский виджет проходит 13.1–13.3, реальная сцена — 13.5 с работами Epic 10. Проверка повторяемости 12.3 следует этим циклам и не блокирует их. Цель суток включает ожидание/исправления; фактические данные ещё не получены. Art, native, physical и публикация имеют отдельные результаты.

## 7. Измерения качества

Phone-бюджет AD-13 уже принят: 30 fps, ≥95% интервалов ≤34 ms, P99 ≤50 ms, без warm stall >100 ms, tap/swipe P95 ≤100 ms; scenario energy delta normal ≤10%, reduced ≤5% к статичному baseline. Hysteresis: saver либо battery≤20% включает reduced, выход при saver off и battery≥25%; UNKNOWN → reduced. Эти числа не возвращаются в открытый старый OQ-7.

Протокол фиксирует устройство/OS/build/launcher/host, версии/hashes, яркость и режим экрана, baseline, длительность, normal/reduced/off и комбинации сигналов. Widget отдельно и несколько widgets совместно с обоями получают собственные заранее заданные технические бюджеты; перенос Wear percent/hour недопустим. Самый тяжёлый комплект определяется измерением, не названием. Только физические результаты закрывают физические gates.

Базовые телефонные проверки Pixel, Samsung и HONOR сохраняются; их сужение — отдельное решение владельца. Со слов владельца ранее были HONOR, планшет Samsung и Xiaomi Watch 2; модель/OS/наличие конкретного устройства перепроверяются перед использованием. Планшет не заменяет телефон Samsung, наличие Watch 2 не относится к новой phone-готовности. Emulator дополняет эти проверки.

## 8. Эксперимент и стоимость поддержки

SM-1 сохраняет ≥100 app installs за 20 календарных дней; исходная семантика магазина не переименовывается в unique users или active surfaces. SM-2/SM-3 остаются историческими 10+ отдельными phone/Wear package installs и неприменимы новому phone-составу. Новые SM-5…SM-7 требуют своего источника/деноминатора/порога до пилота; новый ID не наследует старую цель автоматически.

Встроенная продуктовая аналитика отложена. Ручные наблюдения, добровольные самоотчёты и консоль магазина имеют разный уровень доказательств. CTA, UNKNOWN и локальная конфигурация не становятся подтверждённым применением. Для каждого отчёта сохраняются источник, компонент/версия, период, определение и ограничения.

Dogfooding Якова отделён от 5–7 внешних участников, использующих оформление семь дней. Самостоятельная установка, привлекательность, свободное сочетание, сохранение, батарея и ненавязчивость оцениваются после установки и в конце недели. Коммерческий интерес к будущим темам — качественный сигнал, не доказанная готовность платить. Пилот дополняет отдельное 20-дневное публичное окно.

Повторные вендорские fixes/regression после общей основы — не более двух рабочих дней на релиз. Первичное research учитывается отдельно; два последовательных превышения требуют решения Якова о сужении поддержки или NO-GO. Счётчик скачиваний не отменяет этот критерий. Недобор установок на двадцатый день не запускает автоматическое закрытие.

## 9. Отложенные возможности и сохранённые альтернативы

- **Wear OS:** прежние время/дата/заряд часов, active accent, AOD, ручная активация и доставка сохраняются со своими FR-12…15 и evidence. При возврате переоцениваются продуктовый scope и актуальные платформенные условия. Не наследуются widget-данные и не удаляются старые результаты.
- **Монетизация:** все текущие комплекты бесплатны, доступ ранних пользователей к полученному бесплатному контенту не отзывается. Прежний Brief предполагал поштучные полные наборы, brain dump допускал подписку; новое направление оставляет модель/порог отдельным решением после появления аудитории. Оплата и entitlement сейчас не реализуются.
- **Remote Config:** необязательные будущие анонсы обновлений, готовящихся тем и других приложений владельца; провайдер/архитектура не выбраны. Это не доставка арта и не обязательный сервер.
- **Push:** по отдельному решению после первого выпуска, с источником/доставкой/стоимостью и отдельным согласием пользователя. Разрешение ОС не согласие на любые маркетинговые сообщения; отказ не ограничивает оформление. Локальное «Что нового» работает без push.
- **Внутренний редактор/универсальный engine:** ранний замысел инструмента при высокой стоимости производства сохранён, но не нужен для реализации навыка и шаблонов. Автоматизируются подтверждённые повторяемые операции, не художественное согласование.
- **Референсы Horizon/Walley/Facer и старые скриншоты:** исторический источник визуального качества и удобства. Не доказательство оригинальности категории, не лицензия, не активные требования к WFF или общей палитре хаба.

## 10. Минимум контента и окончательный состав

Решение 17 сентября заменяет прежнее предположение об обязательном полном комплекте: для оценки первой поставки нужен хотя бы один принятый самостоятельный продукт. Первый инженерный выход — авторский виджет, затем настоящая сцена. Окончательный состав и дата принимаются в 13.4/14.6; подготовка процесса не объявляет widget-only release готовым. Десять тем остаются ориентиром. Контур/fixture/непринятый HTML не заполняют публичную коллекцию.
