
# Производство самостоятельного контента и комплектов

Действует [решение 17 сентября](../../../sprint-change-proposal-2026-09-17.md); оно заменяет обязательность пары и предварительного fixture rehearsal из решения 9 сентября. Скилл: [livosphere-content](../../../../../.agents/skills/livosphere-content/SKILL.md).

## Единица производства

`wallpapers/<id>` и `widgets/<id>` — самостоятельные продукты со своими дизайном, поведением, preview и приёмкой. `sets/<id>` — необязательная художественная связь частей; она не связывает настройки или runtime. Виджет не ждёт создания обоев. S/M/L сохраняются; новые обои имеют четыре фазы и авторское движение объектов. Стили и конкретные эффекты принимает владелец.

## Маршруты

| Режим | Художественный путь | Проверяемый выход |
| --- | --- | --- |
| widget | brief → HTML S/M/L → AP-HTML | Самостоятельные читаемые часы; без image gate обоев |
| wallpaper | brief → статичная композиция → AP-IMAGE → HTML фаз/движений → AP-HTML | Настоящая выбранная сцена; собственные объекты/эффекты |
| set | Применимые стадии каждой включённой части | Связь точных ревизий; принятие одной не принимает другую |

После approvals: Android-адаптация → manifest/catalog → выбранные tests/build/native path → APK владельцу. Native mismatch возвращается на художественное решение. Скилл не снимает art gates и не считает PNG/HTML установленной поверхностью.

## Материалы одного продукта

В выбранной UX-области хранятся `DESIGN.md`, `EXPERIENCE.md`, `approval.md`, preview и исходники/ссылки provenance. Для комплекта добавляется `sets/<id>/STYLE.md` со связями, без дублирования локальных решений. Технические exports/manifests живут в delivery-структуре из architecture; в UX не создаётся второй runtime registry.

Шаблоны скилла задают brief, содержимое HTML-review и handoff. Копируются только применимые поля. Отсутствующая поверхность отмечается N/A с причиной; выдуманный approval или dummy wallpaper ради validator запрещён. Текущая schema2 требует пару; поддержку самостоятельного пакета реализует 13.3 по [phone contracts](../../../architecture/architecture-Livosphere-2026-09-01/phone-contracts.md).

## Прототип и приёмка

Для часов нужны отдельные S/M/L в реальном viewport, светлый/тёмный фон, проверка времени/даты и предусмотренного нажатия. Произвольная browser-анимация не обещает RemoteViews-возможность. Для обоев — четыре окружения, отдельный запуск каждого принятого эффекта, уровни, stop/reduced/off и предусмотренные триггеры. Review-controls не становятся автоматически Android settings. Системный шаг маркируется как модель, без ложной установки.

AP-IMAGE относится к выбранной картинке обоев; AP-HTML — к точной ревизии выбранных поверхностей и поведения. Изменение принятой детали требует обновлённого решения. Общие hub tokens и навигация сохраняются; карточка показывает только присутствующие поверхности.

## Практическая проверка процесса

12.1/12.2 готовят инструкции и шаблоны. 13.1–13.3 дают первый авторский виджет в APK. 13.5 проводит следующий цикл на реальной сцене; необходимые части Epic 10 выполняются на ней. 12.3 оценивает оба реальных цикла, ручные действия, повторное использование и время. Развитие тестовой сцены и отдельный технический rehearsal не блокируют первый продукт.

Цель ≤24 часов включает ожидание и исправления. Без фактического цикла скорость не доказана; срок не разрешает молча упрощать замысел. Physical/battery/store и публикация остаются отдельными gates. Скилл не создаёт расписание и не публикует приложение автоматически.
