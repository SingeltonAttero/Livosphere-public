# Livosphere Hub — опыт телефонных наборов

## Действующая коррекция владельца — 18 сентября 2026

Три самостоятельные вкладки **Обои · Виджеты · Ещё**. Это заменяет раннюю карусель
с информационной панелью и переключателем поверхностей на одном экране.

- Обои: изображение от края до края окна, включая фон системных баров. Внизу
  полупрозрачная «Установить обои», затем миниатюра следующей сцены. Горизонтальный свайп
  и нажатие на миниатюру меняют выбранные обои; на последней миниатюра ведёт к первой.
  «Все обои» вверху открывает общий список с миниатюрами и названиями: выбор сразу
  возвращает к нужной сцене. Back возвращает без смены выбора. Нет описаний или
  блока свойств поверх основного арта. Установка относится
  к показанному target; до его подтверждения CTA недоступен. Ошибки ведут в помощь.
- Виджеты: отдельная вертикальная LazyColumn, превью каждого авторского clock M,
  название и S/M/L. В ленте нет кнопок установки: нажатие на виджет открывает его
  карточку с крупным preview, выбором размера и действием по нажатию.
  «Установить виджет» находится только в карточке и передаёт выбранные настройки
  системному pin-пути. Другие часы выбираются в ленте. Выбор обоев и позиция ленты
  сохраняются при возврате.
- Ещё: кнопки перехода «Настройки», «Помощь с установкой», «Как установить».
  Настройки и прежний экран устройств вложены сюда. «Назад» и системный Back возвращают
  на Ещё. Нижняя навигация содержит ровно три пункта и остаётся доступной.

На обоях навигация нейтральная тёмная и прозрачная; на остальных вкладках сохраняется
светлая оболочка hub. Цвета не зависят от выбранного арта. Векторные иконки 24dp,
контролы ≥48dp; нижние отступы измеряются по фактической высоте navbar и safe insets.
Текст масштабируется системой, без декоративных автоматических циклов и заставок.

Установка обоев и часов по-прежнему требует подтверждения Android; возврат из системы
не доказывает ACTIVE. Предыдущие H1/H4 planning mocks ниже исторические.
Проверки и APK: [checkpoint](../../../../development/checkpoint-hub-carousel.md).

## Foundation

Compose-хаб управляет локальной бесплатной коллекцией живых обоев и виджетов часов. [DESIGN](DESIGN.md) сохраняет независимую оболочку hub03.1; её расширение до витрины и конфигурации часов выполнено по принятому плану и делегированию. Реальные обои, AppWidget и системные маршруты принадлежат своим границам; этот контракт не утверждает их реализацию.

Базовый путь доступен offline, без аккаунта/геолокации/опасных разрешений. Новые наборы приходят обновлением приложения. Remote Config остаётся отдельной будущей гипотезой анонсов; нет обязательного push, покупки или загрузки тем в этой IA.

## State Patterns

### Обои A и просмотр B

| Событие | Просмотр/черновик | Применённая поверхность |
|---|---|---|
| Применены A; открыть набор B | browsing=B, preview=B | A и его сохранённые настройки без изменения |
| Системный preview B | B получает изолированное preview-состояние | A продолжает работу |
| Отмена/Back из B | Вернуться к B, можно выбрать A/другой набор | A остаётся применённым; нет toast об успехе B |
| Подтверждение системой B | Повторно прочитать доступные факты | B подтверждается только валидным наблюдением нужной поверхности; иначе UNKNOWN |
| Сохранить настройки B из его карточки | Явно подписано «Настройки обоев B» | Изменяет preference B, не A; после будущего применения B использует его preference |
| Preview/asset B недоступен | Локальная ошибка preview, повтор | Рабочие A и доступный проверенный apply route не блокируются только ошибкой иллюстрации |

Прямой путь X1 — `ACTION_CHANGE_LIVE_WALLPAPER` для выбранного component, fallback — `ACTION_LIVE_WALLPAPER_CHOOSER`, когда он доступен. Системный chooser не доказывает выбор B; HOME/LOCK наблюдаются независимо. Known unsupported/policy block объясняется до бесполезного действия. UNKNOWN применения не запрещает известный доступный маршрут.

### Новый/существующий widget

| Условие | Поведение |
|---|---|
| H4 → H10, новый pin flow | Выбрать theme/size/clock target в черновике с request token; неизвестный appWidgetId не заменять фиктивным; валидировать и перейти к X2. Не полагаться на автоматический запуск configuration Activity из requestPin |
| Pin поддержан/запрос принят | Дождаться решения host; не считать requestPinAppWidget=true размещением |
| Success callback | Связать persistent request token и draft с полученным валидным own ID, проверить provider/host факты, atomic commit once и initial update; поздний callback не перетирает уже перенастроенный widget; хранить доказательство добавления в узком scope callback, не универсальный факт видимости |
| Cancel/no callback/process death | Нет синтетического success и нет вывода «удалён»; по resume перечитать fresh own IDs и состояние pending request; stale request не присваивает ID текущий browsing state, повтор не должен размножать подтверждённый ID |
| Pin unsupported/rejected | H5 предлагает штатный picker лаунчера с нужным provider/размером; не обещает программный launch любого OEM picker |
| Host начал configuration с ID | Валидировать ID и mode; инициализировать результат как cancelled; подтвердить result OK только после успешного сохранения и initial update. Pending pin draft передать по коррелированному request, без глобального last-selected-set |
| Picker без hub draft | Выбрать набор/размер/clock app в H10 для переданного ID; нельзя зависеть от последней просмотренной карточки |
| Configuration cancelled/invalid ID | Не сохранять размещённый экземпляр; discard draft/возврат. При edit существующего ID прежние значения остаются |
| Reconfigure A1 / B1 | Сохранить только выбранный ID; другой экземпляр/обои независимы |
| Host resize/restore/delete | Адаптировать layout к предоставленной геометрии; remap ID при restore; удалить только отсутствующий ID по подтверждённому lifecycle, не по возврату из хаба |
| Clock target удалён/не запускается | Сохранить часы и время, открыть локальный recovery/выбор нового target; не выдавать открытие магазина/хаба за clock app |

Точный персистентный протокол и native границы — в [архитектуре](../../../architecture/architecture-Livosphere-2026-09-01/ARCHITECTURE-SPINE.md); контракт поверхности — [widgets/EXPERIENCE](../widgets/EXPERIENCE.md). Callback не имеет ветки отказа; его отсутствие сохраняет неопределённость. Не требуется опасный список установленных пакетов `QUERY_ALL_PACKAGES`.

### Покрытие IA и восстановление

| Поверхность | Обязательные состояния |
|---|---|
| H1/H4 | Cold load локального registry, selection, быстрый выбор, offline, empty release collection, missing preview, known blocker, normal/reduced; empty не показывает debug-набор |

| H3/H7 | Сохранённые/черновые настройки, supported/unsupported, power/reduced cap, ошибка сохранения с сохранённым вводом и прежним значением |
| H5/H8 | Нет handler, policy block, неподдержанный host, ошибка внешней ссылки; проверенный fallback/Back, отсутствие сети не мешает локальной помощи |
| H9 | Есть/нет новых локальных заметок, закрытие и повторное открытие по запросу |
| H10 | Новый draft/pin pending/host configuration/edit, loading handlers, empty handlers, invalid/deleted ID, save error, cancelled, restored ID |
| X1/X2/X3 | Внешняя система: открыта/возврат/cancel/error/UNKNOWN; аутентификация на LOCK не обходится |
| O1 | Inputs incomplete, AP-IMAGE pending/accepted, AP-HTML pending/accepted, native mismatch, evidence PASS/FAIL/UNKNOWN; в consumer UI нет admin-dashboard |

Пропускаемое знакомство может предложить доступное действие; оно не ставится перед ним обязательным wizard. Повторное приглашение при подтверждённо не применённых обоях — не чаще раза в семь дней. UNKNOWN не запускает такой повтор. Все интерактивные controls имеют normal/pressed/focus/disabled semantics; disabled всегда сопровождается конкретной причиной, если препятствие не очевидно.

## Interaction Primitives

Тап/кнопки — основной путь. Back сохраняет уже применённое, отменяет несохранённый configuration draft. Нет swipe-only выбора набора/размера, вложенных жестов на карточке или обязательного long-press в управляемом хабом пути. Если fallback требует long-press у OEM, локальная инструкция описывает именно проверенный host, а не имитирует его.

Семантика и CTA обновляются сразу, независимо от 440/220/160ms shell motion. Новый выбор прерывает старый; при паузе/возврате нет очереди replay. Reduced хаба не меняет настройки обоев и не обещает изменения поведения чужого host.

## Accessibility Floor

- Android hit area ≥48dp; spacing между соседними целями ≥8dp. HTML reference использует ≥48 CSS px и не подтверждает native размер.
- Масштаб текста 200%, 320dp и landscape: перенос строк, доступные Save/Cancel/Back, одна прокрутка, safe areas и отсутствие перекрытого focus.
- Семантика Compose: роль/имя/selected/stateDescription, порядок focus как порядок чтения. Обновление статуса озвучивается один раз, время не создаёт announcements каждую секунду.
- Meaningful preview имеет краткое описание; декоративные элементы/ghost скрыты от TalkBack. Цвет не единственный признак выбора/ошибки.
- Reduced прекращает shell motion сразу; новые выборы не ждут эффекта. Арт-preview и widget читаемость проверяются отдельно.
- Ошибка формы остаётся у поля, успешные значения не теряются; при нескольких ошибках focus переводится на их сводку с доступным переходом к полю.

Визуальный порог задан `{colors.text}`, `{colors.text-secondary}`, `{colors.primary}` и `{colors.on-primary}` в DESIGN. Светлая база при системной тёмной теме сохраняет собственную палитру; ночная фаза обоев не меняет UI-токены.

## Responsive & Platform

375×812 normal: H1/H4 показывают главное действие без декоративной прокрутки; на малой высоте/320dp/200% разрешена прокрутка и меньшая площадь арта. H10 опирается на фактические границы host. S/M/L — семантические варианты, а не гарантированное число ячеек любого лаунчера.

HOME является основной поверхностью виджета. LOCK показывается как доступный путь только для подтверждённого сочетания устройства, ОС, host и route; неизвестность не запрещает HOME. Открытие выбранных часов на LOCK проходит системную аутентификацию, если она требуется. Часы не заменяют штатные lock-screen часы.

## Inspiration & Anti-patterns

Сохраняются прежние принятые принципы: оформление перед диагностикой, доступная системная примерка перед help, самостоятельная оболочка. Отклонённые hub02 и Wear-макеты остаются историей. Успех в браузерном иллюстраторе не переносится на apply/pin, а количество картинок не доказывает готовность коллекции.

## Key Flows

### UJ-1. Илья выбирает оформление и размещает части

1. Илья открывает H1, выбирает A → H4 «Обои» → «Примерить обои».
2. Подтверждает A в X1, затем просматривает B; отменённый preview B сохраняет A.
3. Выбирает B «Часы», в H10 задаёт размер/clock app и подтверждает размещение в X2.
4. **Кульминация:** работают обои A и часы B; Илья может добавить ещё A1/B2, не заменяя первый widget.

Отмена H10/X2 сохраняет прежние части. No callback → повторная проверка и UNKNOWN, pin unavailable → проверенный picker fallback.

### UJ-2. Илья настраивает оформление и продолжает пользоваться телефоном

1. Илья открывает H2/H6 и видит независимые обои, A1 и B1.
2. Меняет уровень эффектов в H7 именованных обоев либо clock app для B1 через H10.
3. **Кульминация:** только выбранное значение сохранено; A1 и другие поверхности продолжают работу.

Сбой Save сохраняет прежние данные; удалённый target/ID объясняется с маршрутом восстановления. H8/H9 остаются доступны по запросу.

### UJ-3. Яков выпускает следующий комплект

1. Яков проходит [контракт комплекта](../sets/CONTRACT.md), отдельно принимая изображение и HTML.
2. Набор получает свои документы/preview/metadata, shell не меняется.
3. После native-адаптации, целевых проверок и release-процесса новая версия приложения доставляет локальный набор.
4. **Кульминация:** H1 показывает новый release-набор и сохраняет ранее применённые обои и экземпляры часов.

Непринятый art/debug-«Контур» не маскируют пустую release collection; обновление с missing ID использует явный migration/recovery contract, не молчаливую подстановку темы.

### UJ-4. Илья сталкивается с ограничением

1. Илья запрашивает LOCK-размещение или сталкивается с недоступным pin/clock handler.
2. H5/H6 показывает конкретное ограничение и доступный проверенный путь; HOME остаётся доступным.
3. **Кульминация:** понятен следующий шаг без ложной установки и без навязчивой диагностики перед обычным preview.

Policy/auth не обходятся. UNKNOWN остаётся UNKNOWN, cancel не ошибка.

## Самостоятельные сценарии — 2026-09-18

[Решение владельца](../../../decision-2026-09-18-separate-install-flows.md): обои и виджеты имеют отдельные вкладки/карточки/установку. Общая кнопка установки комплекта не предусмотрена. Упаковка widget-only является отдельным техническим остатком 13.3 и не блокирует текущие два flow.

Ещё → Помощь с установкой показывает именованные известные Android экземпляры часов, размеры и настройку конкретного ID. Bound не означает видимость HOME/LOCK. Удаление — инструкция и переход на HOME, без удаления из хаба; сведения перечитываются после возврата. Ошибка списка отличается от пустого списка. Настройки подписывают выбранные обои; после сбоя сохранения доступны несохранённое значение, повтор и отмена.
